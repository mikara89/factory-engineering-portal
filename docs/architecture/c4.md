# C4 architecture views

The diagrams use C4 levels to show system context, containers, and components. The named containers and components describe logical boundaries. They are not all separate hosted services.

The Factory color legend is shown in the [architecture overview](overview.md#color-legend). The public portal remains outside the trusted engineering execution flow.

Each box names its C4 element type in brackets. A dashed frame marks a system or container boundary.

## System context

```mermaid
---
title: Factory Engineering system context
---
flowchart TB
    engineer(["<b>Engineer</b><br/><small>[Person]</small><br/>Defines work and reviews engineering proposals"])

    subgraph factory["Factory Engineering · system boundary"]
        product["<b>Factory Engineering workflow</b><br/><small>[Software System]</small><br/>Governs work, agent execution, verification, and engineering draft publication"]
    end

    model["<b>Model provider</b><br/><small>[External Software System]</small><br/>Provides model responses through the trusted broker"]
    portal["<b>Proposed public portal</b><br/><small>[External Software System]</small><br/>Will serve reviewed documentation as a static site"]
    github["<b>GitHub</b><br/><small>[External Software System]</small><br/>Hosts repositories, Actions, pull requests, and Pages"]

    engineer -->|"Submits or reviews engineering work"| product
    engineer -->|"Reads public documentation"| portal
    product -->|"Sends approved requests through the broker"| model
    product -->|"Proposes reviewed public content through a draft PR"| portal
    product -->|"Uses repositories and Actions"| github
    portal -->|"Hosted with GitHub Pages"| github
```

## Container view

```mermaid
---
title: Engineering and public documentation containers
---
flowchart TB
    engineer(["<b>Engineer</b><br/><small>[Person]</small><br/>Reviews engineering and content proposals"])

    subgraph factory["Factory Engineering · system boundary"]
        productRepo["<b>Product repository</b><br/><small>[Container: Private GitHub repository]</small><br/>Product code and reviewed public content source"]
        controlRepo["<b>Control repository</b><br/><small>[Container: Private GitHub repository]</small><br/>Trusted workflows, approvals, and durable control state"]
        engineeringActions["<b>Engineering Actions</b><br/><small>[Container: GitHub Actions]</small><br/>Runs the engineering workflow with role-specific jobs"]
        sandbox["<b>Agent sandbox</b><br/><small>[Container: Disposable container]</small><br/>Runs untrusted agent tool commands"]
        verifier["<b>Protected verifier</b><br/><small>[Container: Separate workflow job]</small><br/>Checks an exact candidate with protected tests"]
        productPublisher["<b>Engineering publisher</b><br/><small>[Container: Scoped credentials]</small><br/>Creates an authorized engineering draft PR"]
        portalProposal["<b>Portal proposal workflow</b><br/><small>[Container: Manual GitHub Actions workflow]</small><br/>Validates allowlisted content and prepares a portal draft PR"]
    end

    model["<b>Model provider</b><br/><small>[External Software System]</small><br/>External model endpoint"]
    portal["<b>Proposed public portal</b><br/><small>[External Software System]</small><br/>Static GitHub Pages site"]
    github["<b>GitHub</b><br/><small>[External Software System]</small><br/>Hosts repositories, Actions, pull requests, and Pages"]

    engineer -->|"Creates and reviews product changes"| productRepo
    productRepo -->|"Starts reviewed engineering workflows"| engineeringActions
    controlRepo -->|"Supplies trusted workflow and state inputs"| engineeringActions
    engineeringActions -->|"Starts bounded agent execution"| sandbox
    engineeringActions --->|"Requests model output through the broker"| model
    engineeringActions -->|"Submits immutable candidate"| verifier
    verifier -->|"Supplies verified result and evidence"| productPublisher
    productPublisher -->|"Creates engineering draft PR"| productRepo
    productRepo ----->|"Owner starts from an exact reviewed commit"| portalProposal
    portalProposal -->|"Creates a portal draft PR with portal-only access"| portal
    engineer -->|"Reads public documentation"| portal
    portal -->|"Hosted with GitHub Pages"| github

    classDef person fill:#fef3c7,stroke:#d97706,color:#111827;
    classDef source fill:#dbeafe,stroke:#2563eb,color:#0f172a;
    classDef control fill:#ede9fe,stroke:#7c3aed,color:#1f2937;
    classDef agent fill:#ffedd5,stroke:#ea5800,color:#431407;
    classDef verify fill:#dcfce7,stroke:#16a34a,color:#052e16;
    classDef publish fill:#fee2e2,stroke:#dc2626,color:#450a0a;
    classDef infra fill:#e5e7eb,stroke:#6b7280,color:#111827;

    class engineer person;
    class productRepo source;
    class controlRepo,engineeringActions control;
    class sandbox,model agent;
    class verifier verify;
    class productPublisher publish;
    class portalProposal,portal,github infra;
    style factory fill:transparent,stroke:#64748b,stroke-dasharray:6 4;
```

The portal proposal workflow does not read the control repository. It has no connection to engineering execution.

## Component view: portal proposal workflow

```mermaid
---
title: Manual public content proposal components
---
flowchart TB
    source["<b>Product repository</b><br/><small>[Container: Private GitHub repository]</small><br/>Reviewed public content and workflow source"]
    control["<b>Control repository</b><br/><small>[Container: Private GitHub repository]</small><br/>Trusted engineering state; not available to this workflow"]

    subgraph proposal["Product repository · manual proposal workflow"]
        commitCheck["<b>Source commit check</b><br/><small>[Component: Trusted workflow]</small><br/>Requires the exact reviewed default-branch commit"]
        allowlist["<b>Public content validator</b><br/><small>[Component: Python]</small><br/>Rejects unexpected paths and unsupported content"]
        preparer["<b>Deterministic update preparer</b><br/><small>[Component: Python]</small><br/>Copies only approved content and derives stable identity"]
        reconciler["<b>Duplicate and conflict checks</b><br/><small>[Component: GitHub API]</small><br/>Reconciles matching proposals and stops on uncertainty"]
        app["<b>Portal publisher App</b><br/><small>[Component: Portal-only installation]</small><br/>Creates a branch and draft PR"]
    end

    portal["<b>Portal repository</b><br/><small>[Container: Proposed public GitHub repository]</small><br/>Static site source and reviewed update branches"]

    source -->|"Manual dispatch at reviewed commit"| commitCheck
    commitCheck -->|"Passes exact source revision"| allowlist
    allowlist -->|"Passes validated content"| preparer
    preparer -->|"Passes deterministic identity and file set"| reconciler
    reconciler -->|"Allows one write only when state is clear"| app
    app -->|"Creates portal branch and draft PR"| portal

    classDef source fill:#dbeafe,stroke:#2563eb,color:#0f172a;
    classDef control fill:#ede9fe,stroke:#7c3aed,color:#1f2937;
    classDef publish fill:#fee2e2,stroke:#dc2626,color:#450a0a;
    classDef infra fill:#e5e7eb,stroke:#6b7280,color:#111827;

    class source source;
    class control control;
    class commitCheck,allowlist,preparer,reconciler,portal infra;
    class app publish;
    style control stroke-dasharray:4 3;
    style proposal fill:transparent,stroke:#64748b,stroke-dasharray:6 4;
```

The control repository is shown to make the boundary clear. The portal proposal workflow has no relationship to it. The portal cannot authorize work or write back to a Factory repository.
