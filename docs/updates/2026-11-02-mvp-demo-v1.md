## The demo app

TaskFlow is a small task list that the project built for the demo. It has one deliberate bug: when you select **Open**, the list also shows the completed tasks. The cause is a status filter that is sensitive to case.

## Part 1 — Three use cases

### Use case 1: success

1. A person writes a GitHub issue with three requirements and adds the `factory` label.
2. Factory imports the issue as a work item. Nothing runs yet.
3. A triage agent reads the issue and the code. It drafts a work request with requirements, checks, and allowed paths.
4. The owner approves the work request. Only an approved request can start a run.
5. Factory shows the exact attempt, base commit, model, and money limit. The owner confirms the live run.
6. A coding agent works in an isolated container. It can change only the allowed paths.
7. Factory runs the checks itself: build, unit tests, acceptance tests, and a browser check. The agent cannot change the acceptance tests or the browser check.
8. A reviewer checks the diff, the screenshots, and each requirement. The reviewer gives four scores and approves.
9. The owner opens a draft pull request. It holds exactly the verified files. Nothing merges by itself.

### Use case 2: the reviewer requests changes

The first attempt passed all checks, but the reviewer did not approve it. Two tests checked the same thing, and one requirement had no unit test. The reviewer requested two changes, one instruction for each line.

Factory started a second attempt from the first attempt's changes. The second attempt's task included the requested changes word for word. The second attempt did both changes and passed all checks. The reviewer approved it, and the owner opened a draft pull request.

### Use case 3: a scripted safety test

A scripted agent fixed the bug and also changed `README.md`, which is outside the allowed paths. All four checks passed, but Factory refused the candidate. Approval and publication stayed blocked.

This use case is a dry run with fixed agent steps. It does not show an autonomous AI decision. It shows that passing tests are not enough: a change must also stay inside its scope.

## Part 2 — Experiments, scores, and the advisory judge

### Experiments

An experiment compares two finished runs of the same task. Both runs start from the same base commit, with the same approved work request and the same hidden tests. A reviewer scores the two patches as A and B, in a random order, without their configuration, results, or cost. After the scores are submitted, the experiment shows which run was A and which was B.

The video shows recorded experiments. Agents scored them at the owner's request: Claude Code scored five, and Codex scored four. The experiment notes record that these reviews were not blind or not fully blind. With this small number of runs, a score difference is no proof.

### Advisory judge

The advisory judge is a second model that reads a fixed evidence packet of a finished run. It proposes four scores and reports risks with their evidence. Its advice never decides a requirement, approves a run, or publishes a change.

Factory keeps the judge's scores hidden until the review scores are locked. In the video, the judge proposed lower correctness and test-quality scores than the review. One reported risk was useful: the evidence packet did not contain the acceptance-check result. The project recorded that gap as a defect.

## What the demo does not prove

- The reviews in the videos were done by Claude Code at the owner's request. They are not independent human reviews.
- The demo uses one small app with one deliberate bug. It does not show results on large or unfamiliar code.
- The demo does not establish that Factory saves engineering time. That measurement is paused.
- The experiment scores are agent scores and not blind. The judge's calibration and benefit are not accepted.
- The control plane restarted once during a review in Part 1. The saved verdicts and scores were kept, and the video marks the cut.
- Issue intake, publication, and merge stay manual. No pull request in the demo was merged, and nothing was deployed.
